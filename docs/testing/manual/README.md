# تست دستی بای‌مانی و اتصال به استرپی و فرانت

> به‌روزرسانی: ۲۰۲۶-۱۱-۲۵. این پوشه روش اجرا، دادهٔ آماده و قالب ثابت سناریوی تست دستی است.
> مرجع API و هویت: [قرارداد اتصال](../../integration/ByeMoney-Strapi-Integration.md) و [ماتریس دسترسی](../../architecture/Permissions-Matrix.md).
> این سند روش تست است، نه سند پذیرش؛ پذیرش فقط در [گزارش شواهد](../Verification-Summary.md) ثبت می‌شود.

## ۱. پیش‌نیاز اجرای محلی

| مورد | مقدار محلی | وضعیت الان |
|---|---|---|
| PostgreSQL 17 | `localhost:5432` | در حال اجرا (سرویس `postgresql-x64-17`) |
| دیتابیس استرپی | `tarhelahi_server` | موجود، داده دارد (دوره، کالا، کوپن، مبدأ) |
| دیتابیس بای‌مانی | `ByeMoney_Dev` | موجود؛ مهاجرت‌ها هنگام شروع API اعمال می‌شوند |
| Strapi (backend) | `http://localhost:1337` | در حال اجرا |
| ByeMoney (API) | `http://localhost:5000` | در حال اجرا؛ Swagger فقط در `Development` |
| Next.js (front-end) | `http://localhost:3000` | در حال اجرا |
| .NET SDK | ۱۰ | `C:\Program Files\dotnet` (در PATH پیش‌فرض نیست) |
| Node.js | ۲۴ | `node -v` |

```powershell
# ۱) backend

# ۲) ByeMoney — پیش از اجرا متغیر کلید JWT را ست کنید (زیر را ببینید)
cd ..\ByeMoney

dotnet run --project src/ByeMoney.API -- --urls http://localhost:5000

```

### متغیرهای محیطی لازم برای اتصال بای‌مانی به استرپی

| تنظیم بای‌مانی | منبع در استرپی | وضعیت |
|---|---|---|
| `Strapi:JwtSecret` (متغیر: `Strapi__JwtSecret`) | `JWT_SECRET` در `backend/.env` | **در فایل تنظیمات نیست**؛ باید در شل ست شود، وگرنه API با خطای «کلید محرمانه Strapi JWT یافت نشد» بالا نمی‌آید |
| `Strapi:JwtIssuer` / `Strapi:JwtAudience` | `JWT_ISSUER=tarhelahi-strapi` / `JWT_AUDIENCE=byemoney` | در `appsettings.json` هست و با پیش‌فرض استرپی می‌خواند |
| `TarhElahi:BaseUrl` | — | `http://localhost:1337` در `appsettings.Development.json` |
| `TarhElahi:ServiceKey` | `BYEMONEY_SERVICE_KEY` | برابر است (بررسی شد) |
| `FRONTEND_TO_BYEMONEY_SERVICE_KEY` | همان کلید در `front-end/.env.local` | برابر است (بررسی شد) |

نمونهٔ ست کردن در همان شل، پیش از `dotnet run` (مقدار را از `.env` استرپی بردارید، در سند ننویسید):

```powershell
$env:ASPNETCORE_ENVIRONMENT = 'Development'
$env:Strapi__JwtSecret = "<JWT_SECRET از backend/.env>"
```

### آنچه الان کم است

1. **`Strapi__JwtSecret` در هیچ فایل تنظیمات نیست** — بزرگ‌ترین مانع اجرای تازه؛ بدون آن API بالا نمی‌آید.
2. **اکانت ادمین محلی استرپی برای ساخت دادهٔ پایه** — سید با آن دوره/کالا/کوپن می‌سازد؛ یک‌بار یک اکانت اختصاصی بسازید و ایمیل و رمزش را به سید بدهید:
   `npm run strapi admin:create-user -e seed@local.dev -p "<رمز>" -f Seed -l Admin`
   (به‌جای ایمیل و رمز، می‌توانید توکن ادمین را در `SEED_STRAPI_ADMIN_TOKEN` بگذارید.)
3. **کاربر تست با نقش Admin در بای‌مانی** — کاربر عادی استرپی هیچ مجوزی در بای‌مانی ندارد؛ نقش توسط سید در جدول‌های RBAC داده می‌شود.
4. **هدیهٔ خوش‌آمد فقط برای کاربران قدیمی است** — کاربرانی که پیش از اعمال مهاجرت `DisableWelcomeCampaignSeed` ثبت شده‌اند ۵۰ نور هدیه دارند و آن باقی می‌ماند؛ کاربر تازه (مثل خریداران `-Action buyers`) هدیه نمی‌گیرد و با ۰ شروع می‌کند (دیده‌شده در ۲۰۲۶-۱۱-۲۵). «کاربر بدون موجودی» یعنی «بدون شارژ»، نه «صفر نور»؛ موجودی واقعی را پیش از هر سناریو بخوانید.
5. `dotnet` در PATH پیش‌فرض نیست؛ از مسیر کامل `C:\Program Files\dotnet\dotnet.exe` استفاده کنید.

## ۲. داده‌سازی با یک دستور

```powershell
cd ByeMoney\scripts\manual-test

# ساخت یا تکمیل داده (تکرارپذیر؛ دادهٔ تکراری نمی‌سازد)
.\seed.ps1 -Action up -StrapiAdminEmail seed@local.dev -StrapiAdminPassword "<رمز ادمین>"

# فقط بررسی داده از مسیر API، بدون تغییر
.\seed.ps1 -Action verify

# پاک‌سازی و ساخت دوبارهٔ دیتابیس بای‌مانی
.\seed.ps1 -Action reset -AllowDatabaseReset
# سپس API را متوقف و دوباره اجرا کنید تا مهاجرت‌ها اعمال شوند و بعد -Action up

# دستهٔ تازهٔ خریداران برای سناریوهای «سبد و خرید» (۰۲)، «سفارش دستی» (۰۳)، «ارسال و تحویل» (۰۴)، «لغو فیزیکی» (۰۵) و «تسویه و خروج نور» (۰۶)؛ یک بار پیش از اجرا
.\seed.ps1 -Action buyers

# شبیه‌سازی غیرمالی پرچم برگشتی یا هشدار پستی روی قلم Shipped (بدون فراخوانی پستکس واقعی)
.\seed.ps1 -Action shipping-flags -PurchaseId "<guid>" -CarrierFlag return
.\seed.ps1 -Action shipping-flags -PurchaseId "<guid>" -CarrierFlag alert -AlertCode 11304

# دادهٔ سناریوی «تسویه و خروج نور» (۰۶): یک شارژ تأییدشدهٔ دارای نرخ و یک شارژ بدون نرخ روی خریدار خروج
# (پیش‌نیاز: یک بار -Action buyers در همین دسته اجرا شده باشد؛ بدون آن با پیام روشن متوقف می‌شود)
.\seed.ps1 -Action finance

# دادهٔ سناریوی «رسیدگی مالی درگاه» (۰۷): ۵ درخواست شارژ (معلق، تأییدشده، برگشت‌خورده، تعارض بانکی، کارت‌به‌کارت)
# (اگر دستهٔ buyers نباشد، از کاربر نمونهٔ 09120000002 استفاده می‌کند)
.\seed.ps1 -Action gateway-review
```

**قواعد امنیتی سید:**

- اجرا فقط روی `localhost`/`127.0.0.1` مجاز است؛ آدرس غیرلوکال باعث توقف فوری می‌شود.
- `reset` فقط روی نام دیتابیس با پسوند `_Dev`/`_Test`/`_Local` کار می‌کند و سوئیچ `-AllowDatabaseReset` می‌خواهد.
- هیچ سطر دفتر کل (`LedgerEntries`)، کیف پول (`Wallets`) یا درخواست شارژ به‌صورت مستقیم نوشته یا ویرایش نمی‌شود. همهٔ پول از مسیر API ساخته می‌شود: درخواست شارژ کاربر → تأیید ادمین → هدیهٔ ادمین.
- تنها نوشتن مستقیم در دیتابیس: تخصیص نقش `Admin` در جدول‌های RBAC (`UserRoles`)، نقش `administrator` در استرپی (`up_users_role_lnk`) برای دسترسی به پنل ادمین فرانت و پیش‌نمایش استرپی، پرچم `blocked` کاربر استرپی، و پرچم‌های غیرمالی برگشتی/هشدار (`CarrierReturnedAtUtc` / `CarrierAlertCode`) در `-Action shipping-flags` روی قلم `Shipped` برای تست محلی بدون پستکس. هیچ‌کدام اثر مالی ندارند.
- شناسه‌های ساخته‌شده در `ByeMoney/.artifacts/manual-test/seed-state.json` ثبت می‌شوند (این پوشه در Git نیست).
- اگر ساخت دادهٔ پایه لازم نیست (مثلاً فقط کیف پول)، مرحلهٔ استرپی با اعلام هشدار رد می‌شود؛ شناسه‌های قبلی در فایل وضعیت حفظ می‌شوند.
- شروع دوبارهٔ API محدودیت ورود ادمین استرپی (`429`) نمی‌سازد؛ سید یک ورود می‌کند و توکن را نگه می‌دارد. اگر توکن ادمین را از قبل دارید، به‌جای ایمیل و رمز از `$env:SEED_STRAPI_ADMIN_TOKEN` استفاده کنید.
- فایل اسکریپت باید UTF-8 با BOM ذخیره شود؛ PowerShell 5.1 فایل بدون BOM را با کدگذاری اشتباه می‌خواند و متن فارسی آن را می‌شکند.

**دستهٔ خریداران (`-Action buyers`):** هر بار ۲۰ کاربر تازه با شماره‌های آزاد `091200000xx` می‌سازد (۸ کاربر برای سناریوی «سبد و خرید»، ۳ کاربر برای سناریوی «سفارش دستی ادمین»، ۳ کاربر برای سناریوی «ارسال و تحویل»، ۳ کاربر برای سناریوی «لغو کالای فیزیکی»، ۲ کاربر برای سناریوی «تسویه و خروج نور»: `settlementBuyer` و `withdrawalBuyer` و ۱ کاربر برای «رسیدگی مالی درگاه»: `gatewayReviewBuyer`)، موجودی هدف هر نقش را از مسیر شارژ و تأیید ادمین (و برای `cancelPartialBuyer` هدیهٔ ۱۰ نوری از `/api/admin/noor-gifts`) تأمین می‌کند و فقط آخرین دسته را در `buyers.items` فایل وضعیت نگه می‌دارد. خرید دوره برگشت‌ناپذیر است و `reset` مالکیت‌ها را در استرپی پاک نمی‌کند؛ به‌جای `reset` دستهٔ تازه بسازید. آدرس خریداران و دادهٔ پایه به ادمین استرپی نیاز دارد؛ بدون آن خریداران بدون آدرس می‌شوند و `verify` آن را ناموفق گزارش می‌کند.

## ۳. کاربران نمونه و روش ورود

| کاربر | شماره | رمز | چه دارد | ورود در Swagger | ورود در فرانت |
|---|---|---|---|---|---|
| دارای موجودی | `09120000001` | `Manual-Test-2026` | موجودی هدف ۱۰۰ نور (شارژ + هدیهٔ ادمین) | `POST /api/auth/password/login` روی استرپی، سپس توکن در دکمهٔ Authorize | تب ورود → شماره → رمز عبور |
| بدون موجودی | `09120000002` | `Manual-Test-2026` | فقط هدیهٔ خوش‌آمد (اگر فعال باشد) | همان مسیر | همان مسیر |
| ادمین | `09120000003` | `Manual-Test-2026` | نقش `Admin` با هر ۸ مجوز در بای‌مانی | همان مسیر؛ برای مسیرهای `/api/admin/*` | همان مسیر (پنل ادمین فرانت) |
| مسدود | `09120000004` | `Manual-Test-2026` | پرچم `blocked` در استرپی | ورود رد می‌شود (۴۰۰) | پیام «حساب کاربری شما مسدود شده است» |

سید فقط کمبود موجودی را شارژ می‌کند؛ اجرای سناریوها موجودی را بالا می‌برد و اجرای دوبارهٔ سید آن را کم نمی‌کند. اگر «کاربر بدون شارژ» لازم دارید، از `09120000002` استفاده کنید یا با `reset` دیتابیس را از نو بسازید.

برای سناریوی [سبد و خرید](02-cart-and-purchase.md) از این چهار کاربر استفاده نکنید (مالکیت دوره مانع تکرار می‌شود)؛ خریداران آن سناریو با `-Action buyers` ساخته می‌شوند و جدولشان در `buyers.items` فایل وضعیت است.

**گرفتن توکن برای Swagger:**

```powershell
# توکن کاربر را از استرپی بگیرید (بدون پیامک)
$login = Invoke-RestMethod -Uri 'http://localhost:1337/api/auth/password/login' -Method Post `
  -ContentType 'application/json' -Body '{"phoneNumber":"09120000001","password":"Manual-Test-2026"}'
$login.jwt   # این را در Swagger → Authorize → Bearer بگذارید
```

**ورود بدون پیامک:** مسیر `POST /api/auth/password/login` هیچ پیامکی نمی‌فرستد. اگر روزی مسیر OTP لازم شد، شماره‌هایی که با `T` شروع شوند (مثل `T09120000001`) در محیط توسعه کد را در کنسول استرپی چاپ می‌کنند و پیامک نمی‌فرستند.

## ۶. سیاست فراخوانی بیرونی

بدون تأیید جداگانه، هیچ فراخوانی واقعی بانک، پستکس یا پیامک انجام نمی‌شود. وضعیت فعلی:

| مورد | بدون فراخوانی بیرونی ممکن است؟ | راه محلی |
|---|---|---|
| شارژ کیف پول | بله | درخواست شارژ کارت‌به‌کارت + `POST /api/admin/topups/{id}/confirm` |
| هدیهٔ نور | بله | `POST /api/admin/noor-gifts` با هدر `Idempotency-Key` |
| ورود کاربر | بله | ورود با رمز؛ برای OTP شمارهٔ `T…` |
| خرید دوره | بله | با موجودی کیف پول؛ قیمت از استرپی خوانده می‌شود |
| خرید کالای فیزیکی | تا پیش از ساخت مرسوله | نیازمند مبدأ و تنظیمات ارسال؛ اگر `costMode=postex` باشد هزینهٔ ارسال از پستکس پرسیده می‌شود ← **نیازمند تأیید** |
| ساخت مرسوله و رهگیری | **خیر** | پستکس واقعی؛ باید متوقف شود (برای ثبت کد دستی از `PUT .../delivery-status` و برای برگشتی/هشدار محلی از `.\seed.ps1 -Action shipping-flags` استفاده کنید) |
| شارژ واقعی درگاه (SEP) | **خیر** | یا تأیید ادمین، یا ماک موجود فرانت (`SEP_MOCK_ENABLED`) |
| تسویهٔ سفارش‌ها و خروج نور | بله | بستن دورهٔ تسویه فقط تگ است؛ خروج نور از مسیر ادمین (`/api/admin/noor-withdrawals`) و واریز واقعی بیرون سیستم و دستی است (D09/D10) |

## ۷. نکات اجرا

- محدودیت نرخ ورود ادمین استرپی: چند ورود پشت‌سرهم `429` می‌دهد؛ سید یک‌بار وارد می‌شود و توکن را نگه می‌دارد.
- پاسخ `POST /api/topup/requests` برای کارت‌به‌کارت مقدار `amountRial=0` می‌دهد؛ این رفتار درست است (مبلغ ریالی فقط در مسیر درگاه معنا دارد).
- موجودی هدیه جدا شمرده می‌شود (`giftBalance`) و از مسیر خروج قابل برداشت نیست.
- هر سبدی که کالا دارد به آدرس کامل با شهرِ متصل نیاز دارد؛ خریدار بدون آدرس از `checkout` پاسخ عمومی `400 CART_INVALID` می‌گیرد.
- کد تخفیف نامعتبر در `checkout` بای‌مانی هم `400 CART_INVALID` با پیام عمومی است؛ پیام مشخص («یافت نشد»، «غیرفعال»، «ظرفیت تمام شده») را پیش‌نمایش استرپی می‌دهد.
